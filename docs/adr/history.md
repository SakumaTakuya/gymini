# ADR: history

## DayPicker を shadcn/ui Calendar ラッパー経由ではなく直接使用

- **決定**: `react-day-picker` の `DayPicker` を直接インポートし、カスタム `GymDayButton` を組み合わせる
- **理由**: shadcn/ui の Calendar は汎用スタイルパレットを前提としている。FRAME3 は 5 状態のカスタムスタイル（36px サークル・アクセントドット・ring-selected・今日は黒・範囲外はフェード）が必要であり、shadcn のラッパー経由では `classNames` のオーバーライドが複雑になる。

## カレンダーの月・日付状態を URL search params で管理

- **決定**: 選択中の月・日付を TanStack Router の search params（Zod `validateSearch`）で管理する
- **理由**: URL ドリブンな状態管理によりタブ切り替え・ブラウザバックをまたいで状態が保持される。グローバルストアが不要になる。

## TanStack Query の staleTime を用途別に差別化

- **決定**:
  - `workoutDates`（月カレンダー）: `staleTime: 0` + `refetchOnWindowFocus` でタブ復帰時に自動リフレッシュ
  - `workoutsForDate`（日別サマリー）: デフォルト staleTime で同一日付の再選択時はキャッシュを再利用
- **理由**: 月キーは日付変更をまたいでも安定しており（新鮮さが必要）、日付キーはクエリキーが変わると新規フェッチが走るため（再利用が有効）。

## ワークアウトをフルリスト取得してクライアントサイドでフィルタ

- **決定**: 全ワークアウトを取得してから月単位でクライアントフィルタする（月インデックスを持たない）
- **理由**: データ量（数百件）はメモリバジェット内に収まる。月ベースのインデックス管理のオーバーヘッドを避けられる。

## 未来日の選択をブロックしない

- **決定**: 未来日のタップを禁止しない
- **理由**: 事前にワークアウトを計画する用途を許容する。「追加」ボタンから未来日のセッションを開始できる。

## EmptyDayState の「追加」ボタンは `/` へ遷移して startSession を呼ぶ

- **決定**: 空の日のアクションとして `navigate({ to: '/' })` + `startSession(date)` を実行する
- **理由**: モーダルを挟まずにワークアウトセッションをインラインで開始できる。
