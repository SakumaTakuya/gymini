# ADR: exercise-master

## Hook + Store + Repository の 3 層構成

- **決定**: UI → `useExercises` hook → `exerciseMasterStore` → `ExerciseMasterRepository` の依存チェーンを強制する
- **理由**: 初期設計の「Repository のみ」では各 UI コンポーネントが独立した `useState + refresh()` を持ち、`ExerciseMasterSection` と `ExerciseSearchField` 間で状態が同期しない問題が発生した。Zustand キャッシュを単一にすることで同一タブ内のミューテーション伝播と、`storage` イベントを通じたクロスタブ同期を実現する。

## UI が Repository を直接インポートすることを禁止

- **決定**: UI 層（`routes/`, `components/`）から `ExerciseMasterRepository` の直接インポートを禁止する
- **理由**: 直接インポートはストアキャッシュをバイパスするため、ミューテーション後に他のサブスクライバーの状態が更新されない。

## 重複名チェックの大文字小文字の扱い

- **決定**: `create()`/`update()` の一意性チェックは大文字小文字を区別する。`search()` は区別しない。
- **理由**: 意図的な非対称性。「ベンチプレス」と「べんちぷれす」は別の種目として保存可能（厳格な保存）だが、検索ではどちらでもヒットさせる（検索ヒット率優先）。

## 存在しない ID への `remove()` は黙殺（冪等）、`update()` はエラー

- **決定**: `remove()` は存在しない ID に対して黙殺（冪等）。`update()` は存在しない ID に対してエラーを投げる。
- **理由**: `remove()` はクリーンアップ操作であり冪等であることが自然。`update()` は存在を前提とした操作であり、ID が存在しない場合はプログラムバグを示す。

## ワークアウト記録の種目名はスナップショット保存（マスタ変更を追跡しない）

- **決定**: ワークアウト記録保存時に種目名をスナップショットとして保存し、マスタ側の名前変更は履歴に反映しない
- **理由**: 記録時点の名前を保持することでデータ整合性を担保する。カスケード削除・更新の複雑さを回避できる。（`workout` ADR の exerciseName スナップショット保存と同じ判断）
