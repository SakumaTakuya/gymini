# ADR: settings

## settingsStore での localStorage 直接操作（persist ミドルウェア不使用）

- **決定**: Zustand の `persist` ミドルウェアを使わず、localStorage を直接操作する
- **理由**: APIKey は単一の文字列値。JSON のシリアライズ/デシリアライズのオーバーヘッドが不要。（`api-key` ADR と同じ判断）

## APIKey 入力の自動保存にデバウンスとフィードバック表示を採用

- **決定**: キー入力をデバウンスして保存し、自動保存中・完了をユーザーに通知する
- **理由**: キーストロークごとに localStorage へ書き込むのは非効率。自動保存への不安を視覚フィードバックで解消する。

## 空文字列渡しで内部的に削除処理を実行

- **決定**: API キーに空文字列が渡された場合、エラーを投げずに内部で削除処理（状態リセット + キー削除）を実行する
- **理由**: 呼び出し元がブランチを書かずに生のユーザー入力をそのまま渡せる。インターフェースをシンプルに保つ。

## 設定画面の各セクションは hook 経由でストアにアクセスする

- **決定**: 設定画面の各セクションコンポーネントは Repository を直接インポートせず、hook 経由でストアにアクセスする
- **理由**: UI→Hook→Store→Repository の依存チェーンを維持する。他のコンポーネントとのミューテーション同期とクロスタブ変更が確保される。（`exercise-master` ADR と同じ判断）

## 重複名エラーはモーダルではなくインラインで通知する

- **決定**: 種目名の重複エラーはモーダルや toast ではなくフィールド直下のインラインで通知し、再入力で自動クリアする。WAI-ARIA によるスクリーンリーダー対応も付与する。
- **理由**: サイレント失敗はユーザーが原因を把握できない。インライン表示により視覚ユーザーとスクリーンリーダーユーザーの両方に通知できる。モーダルはフォームフローを妨げる。

## ユーザープロファイルの全フィールドをオプショナルに

- **決定**: プロファイルの全フィールドを nullable（オプショナル）にする
- **理由**: B-001（Privacy-by-Design）に基づき、強制入力なしでの利用を可能にする。入力障壁を下げる。AI は部分的なプロファイルでも機能する。

## AI システムプロンプト生成を純粋関数に切り出す

- **決定**: システムプロンプト生成ロジックを純粋関数として定数定義と同一ファイルに置く
- **理由**: テスタビリティと凝集性。システムプロンプトのロジックと定義が同一ファイルに集まり、独立してテスト・変更できる。

## プロファイルはメッセージ送信時にスナップショットで参照する

- **決定**: チャット送信時にストアの現在値を一度だけ読む（リアクティブなサブスクリプションはしない）
- **理由**: プロファイルは会話中に変わることがほぼない。送信タイミングのスナップショット参照により、プロファイル変更のたびにクライアントを再生成する複雑さを避けられる。
